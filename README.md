# 集会QR受付システム

Google Apps Script で動作する集会QR受付システムです。

## ソースコードの正式な保管場所

このGitHubリポジトリの `main` ブランチを、確認済みソースコードの保管場所として使用します。

- `Code.gs`: サーバー側処理
- `Index.html`: 受付画面
- `appsscript.json`: GASプロジェクト設定（GASから取得して管理）
- `.clasp.json`: 各自のGASプロジェクトIDを含むローカル設定。Gitには登録しません。

## 更新方針（手動更新）

GitHubへのコミットだけでは、稼働中のGASは更新されません。GASへの反映は、担当者が差分と動作を確認してから `clasp push` を実行します。Webアプリの公開版を更新するデプロイ操作も別途必要です。

### 初回準備

1. Node.js の LTS 版をインストールします。
2. コマンドプロンプトまたは PowerShell で `npm install -g @google/clasp` を実行します。
3. `clasp login` を実行し、対象GASを編集できるGoogleアカウントでログインします。
4. このリポジトリをPCにクローンします。
5. 対象GASの「プロジェクトの設定」からスクリプトIDを確認します。
6. リポジトリのルートに、次の内容でローカル専用の `.clasp.json` を作成します（値は実際のスクリプトIDに置き換えます）。

```json
{
  "scriptId": "ここにGASのスクリプトID",
  "rootDir": "."
}
```

7. GAS側の現行ファイルとGitHubの内容を照合します。初回は本番GASから取得した内容を別フォルダに `clasp clone` または `clasp pull` し、GitHub版と差分比較してください。GAS側にGitHub未登録の変更があれば、内容を確認してからGitHubへ取り込みます。
8. `appsscript.json` は実際のGASプロジェクトから取得した設定を基準に管理します。設定を推測で作成・置換しないでください。

### 通常の更新手順

1. GitHubから最新の `main` を取得します（`git pull`）。
2. 作業ブランチを作成し、コードを変更します。
3. 差分を確認します（`git diff`）。
4. テスト用GASプロジェクトがある場合は、先にそちらへ反映してテストします。
5. レビュー後に `main` へマージします。
6. 本番用フォルダで最新のGitHubコードとGASのローカルファイルが一致していることを確認し、`clasp push` を実行します。
7. GASエディタまたはWebアプリで動作確認します。
8. Webアプリの公開版を更新する場合だけ、GASの「デプロイを管理」から対象デプロイを編集して新しいバージョンを選択し、更新します。
9. 更新したコミットID、反映日時、確認結果を記録します。

### 重要な注意

- GitHubへの `git push` はGASへの反映ではありません。
- `clasp push` はGASプロジェクト内のファイルを上書きします。必ず差分を確認してから実行してください。
- `clasp push` とWebアプリのデプロイ更新は別操作です。
- 管理者PIN、APIキー、OAuthトークン、個人情報、会員名簿などの秘密情報・実データをGitHubに登録しないでください。
- `.clasp.json`、`.clasprc.json`、認証情報ファイルはコミットしないでください。
- 初回の現行GASとの照合が完了するまでは、本番環境への `clasp push` を行わないでください。
